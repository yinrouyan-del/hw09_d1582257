## 1. 程式用途與執行方式

### 程式用途
本程式協助主辦單位整理「桌遊體驗」與「電影欣賞」兩場活動的報名名單：
- 透過字串處理去除半形空白、轉換為小寫，並拆分成串列（`list`）。
- 運用集合（`set`）去除重複報名，並計算交集（共同參加者）、聯集（全部參加者）及兩個方向的差集（只參加單場者）。
- 透過字典（`dict`）彙整人數與應收費用，輸出完整的報名摘要與通知名單預覽。

## 3. 問題回答

### 問題一：測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？
- **費用計算原因**：
  依據規則，同一人重複報名同一活動只算一位參加者且只收費一次。整理後的桌遊串列為 `['amy', 'ben', 'amy', 'cora']`，其中 `amy` 重複報名了 2 次，因此去重後的實際參加人數為 3 人（amy, ben, cora），應以 3 人計費（3 × 120 = 360 元）。
- **保留與失去的特性**：
  - **轉成 `list`**：
    - **保留**：原始報名的先後順序、重複項目的次數與位置索引。
    - **失去**：原本純文字字串的單一結構（被拆散成元素）。
  - **轉成 `set`**：
    - **保留**：元素的唯一性（自動去重，留下相異的元素值），並獲得快速進行集合運算（交集、差集等）的能力。
    - **失去**：元素的順序性（set 無序且無法使用索引切片）以及原本重複出現的次數資訊。

### 問題二：測試三中，兩場活動只有 3 位不同的人，為什麼是 6 人次、總應收仍是 600 元？請用集合關係與算式說明。
- **集合關係說明**：
  測試三的桌遊去重集合為 `{amy, ben, cora}`，電影去重集合亦為 `{amy, ben, cora}`。
  - 兩場的交集大小為 3（`len(board_set & movie_set) = 3`），代表 3 個人兩場皆有參加。
  - 聯集大小為 3（`len(board_set | movie_set) = 3`），因此「總不重複人數」為 3 人。
- **算式說明**：
  - **報名人次**：依定義為兩場活動各自去重後的人數相加。
    $$\text{報名人次} = \text{桌遊人數 (3)} + \text{電影人數 (3)} = 6 \text{ 人次}$$
    （因為 3 位參加者每人都報名了 2 場，每人貢獻 2 人次）。
  - **總應收金額**：兩場費用獨立計算，每人每場各自付費：
    $$\text{桌遊應收} = 3 \times 120 = 360 \text{ 元}$$
    $$\text{電影應收} = 3 \times 80 = 240 \text{ 元}$$
    $$\text{總應收} = 360 + 240 = 600.00 \text{ 元}$$
